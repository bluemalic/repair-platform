# 09 · 演示脚本（录屏 / 答辩用）

> 这份文件回答一个问题：**给人演示这个项目时，按什么顺序点、每个场景说什么**。
> 目标时长 **6~8 分钟**；每个场景都能单独截出来当短视频（30 秒 ~ 1 分钟）。
>
> 录制前一定先做 §1 的准备——演示数据、口令、统一认证入口都与准备动作有关，
> 状态不对时照着本脚本点会在第二步就卡住。

---

## 1. 录制前准备（约 5 分钟）

| 项 | 值 |
|---|---|
| 管理端 | `http://<站点>:8080/`（演示站：`http://119.91.47.63:8080/`） |
| 学生 / 维修工端（H5） | `http://<站点>:8080/h5/` |
| 页面上的演示账号提示 | 由 `VITE_DEMO_ACCOUNTS` 构建时注入（演示站有） |
| 口令 | 服务器 `.env` 的 `REPAIR_DEMO_PASSWORD`（**不要**在录屏里出现 `.env` 或口令输入框） |

1. **重置演示数据**（会重建 5 个演示账号 + 12 张工单，口令回到配置值）：
   ```bash
   docker compose restart app
   ```
   等 `/actuator/health` 为 `UP`（约 20 秒）。演示模式（`REPAIR_DEMO_ENABLED=true`）在启动时会自动重置。
2. **确认统一认证入口可用**：登录页填学校编码 `gdou` 后能看到「统一认证登录」（演示站已开 Mock IdP，
   见 `docs/05` §4.6；关掉时这一行不显示，场景 9 就跳过）。
3. **浏览器**：两个窗口并排（管理端 + H5），缩放 100%；关掉系统通知 / 微信弹窗。
4. **AI 场景**：确认 `.env` 里 `AI_MODEL_API_KEY` 有余额——问数一次两次模型调用、受理一次两次，
   演示用不了几毛钱，但余额为 0 时会当场报 40004。
5. **提前打开一次**要演示的页面（首屏编译缓存），避免录到白屏。

> 演示数据是**每次重启重建**的，所以"上次演示留下的脏数据"不是问题；反过来，演示中途重启
> 会把刚提交的工单清掉——录完一个场景再改代码/重启。

## 2. 场景清单（按顺序）

### 场景 1 · 学生报修：扫位置码 / 手选公共区域（约 1 分钟）

**角色**：学生 `20260001`（H5）

1. 登录 H5 →「我要报修」→ 点「扫码」：镜头对准 **1号楼 1-101** 的码（演示可手输 `482913`）。
2. 位置自动带出「1号楼 1-101」；切到「手动选位置」，选「图书馆 / 1F-大厅」（公共区域）。
3. 选类别「水电」、紧急度「紧急」、写一句描述 → 提交。

**预期**：工单详情页出现，状态「待派单」。管理端工单列表同步出现这一单。

> **话术**：位置有两个入口——扫房间码，或从位置列表里选（公共区域不可能贴着码等人找）。
> 两条入口落到同一个"位置码"模型上，所以维修工到场核验不用为公共区域写特判。

### 场景 2 · 后勤派单：候选评分（约 1.5 分钟）

**角色**：后勤 `admin`（管理端）

1. 工单列表 → 待派单 → 打开场景 1 的单 →「派单」。
2. 候选列表里指一下每个人的四项明细（技能 / 满意度 / 负载 / 距离）与一句话理由。
3. 选排第一的师傅 → 确认派单。

**预期**：工单变「待接单」；H5 维修工端收到站内通知。

> **话术**：评分**只排序、不自动派单**——什么时候派给谁仍然是调度员的判断，系统只把
> "为什么推荐他"摊开给人看（四项加权，缺数据记中性分）。

### 场景 3 · 维修工接单 → 扫报到场 → 完工（约 1 分钟）

**角色**：维修工 `worker01`（H5）

1. 接单 → 状态「处理中」。
2. 点「到场」→ 扫 **同一张位置码**（或手输）。
3. 完工上报：写处理结果 + 传一张照片。

**预期**：状态「待验收」；管理端时间线上有 接单 / 到场 / 完工 三条记录。

> **话术**：到场必须扫到**这张单对应的位置码**——扫别处的码会被拒（位置校验在服务端），
> 这样"到场时间"是可信的，响应/处理时长才有意义。

### 场景 4 · 学生验收评价（约 30 秒）

**角色**：学生 `20260001`（H5）

1. 打开这一单 → 验收通过 → 5 星 + 一句评价。

**预期**：状态「已完成」；管理端看板的满意度有变化。

> **话术**：评价是幂等的（一个工单只能评一次，唯一索引兜底）；不评价的工单会在 24 小时后
> 被超时调度自动关闭。

### 场景 5 · 统计看板 + Excel 导出（约 1 分钟）

**角色**：后勤 `admin`（管理端）

1. 打开「统计看板」：概览卡 + 趋势 + 类别占比 + 师傅排行，切一下时间范围。
2. 点「导出」→ 打开下载的 xlsx（工作表与页面口径一致）。

> **话术**：看板口径以 `ticket_log` 的动作为准（超时数不是重算阈值），所以和工单时间线永远对得上；
> 导出走同一批聚合查询，不是另写一套 SQL。

### 场景 6 · AI 问数：自然语言 → SQL → 结论（约 1.5 分钟）

**角色**：后勤 `admin`（管理端「AI 问数」）

1. 问：**「最近 7 天每天的报修量」** → 看三个阶段帧（SQL 已定 → 数据 → 结论）+ 图表。
2. 再问一个安全用例：**「查一下每个学生的手机号」** → `40002 不允许查询敏感字段：phone`。

> **话术**：模型只负责"把中文变成一条 SQL"，真正的安全在四层闸门：只读账号、单条 SELECT 白名单、
> 强制注入租户条件（JOIN 进来的表注到 ON）、3 秒超时 + 行数截断。所以"越权/删库"不是靠提示词保证的。
> 第二条问句是故意演示被拦。

### 场景 7 · 师傅排查建议：检索 + 引用（约 1 分钟）

**角色**：维修工 `worker01`（H5 工单详情）或管理端「维修知识库」

1. 工单详情 →「排查建议」→ 展示步骤，每条带**引用来源**（知识库条目标题）。
2. 换一个知识库里没有的问题（现场改一下工单描述）→ 提示"没有匹配的知识条目"，**不调模型**。

> **话术**：建议不是模型凭空想的——先用 MySQL 的 ngram 全文索引从知识库检索，命中的条目作为资料
> 交给模型组织；服务端再核对"模型引用的条目确实在命中列表里"，编造的引用会被剔除。
> 零命中直接返回、不花钱。

### 场景 8 · 平台运营与架构看点（约 1.5 分钟）

**角色**：平台运营（管理端 `?platform=1` 入口）

1. 租户列表：配额（已用/上限）、**统一认证列**、状态。
2. 「开通学校」→ 填编码 + 管理员 → 提交（后台：建库 → 跑租户库迁移 → 在该校库里建管理员）。
3. 行内「统一认证」→ 配置弹窗（协议、密钥只显示"已配置"、必填项校验）→ 保存。
4. 行内「管理员」→ 新增 / 重置口令；「编辑」→ 配额。
5. 切回学校账号：审计日志（谁改了东西）、通知中心。

> **话术**：平台账号**看不到任何学校的业务数据**——这条由服务端的平台域拦截器强制，不靠"这里没写接口"。
> 新开通的学校各自一个 database（数据与结构互不干扰，不是性能隔离）；存量学校可以"搬家 → 逐表校验
> → 切换"，切换只有几秒；定时任务按租户遍历。平台页看不到工单，这是设计不是缺功能。

### 场景 9 · 统一认证登录（约 30 秒，演示站有 Mock IdP）

1. 退出 → 登录页填 `gdou` → 点「统一认证登录」。
2. 跳到 Mock IdP 的身份页（三个演示身份 + 一个"平台里没有的学号"）→ 点 `admin`。
3. 回到管理端，已登录。

> **话术**：这是**登录的第二个入口**，不是第二套登录——发 token、绑租户、写首登改密标记、写登录审计
> 全部复用账号密码那一套。协议做成适配器（CAS / OAuth2 都支持），Mock IdP 只是用来演示；
> token 不进 URL（回调只带一次性登录码），平台也不会因为 IdP 认了就自动建号。

## 3. 录制建议

- **工具**：Windows 自带 `Win + G`（录屏）或 OBS；分辨率 1920×1080，鼠标点击高亮。
- **剪成三段**，方便分别贴到简历/作品集：
  1. 学生与师傅端（场景 1~4，~3.5 分钟）
  2. 管理端与 AI（场景 5~7，~3.5 分钟）
  3. 平台与架构（场景 8~9，~2 分钟）
- **字幕**：每段开头顶一行"这个场景证明什么"（本文件每个场景的 `话术` 就是）。
- **不要录到**：`.env`、口令输入框、浏览器书签栏、微信/邮件通知。

## 4. 常见翻车点

| 现象 | 原因 |
|---|---|
| 登录页没有「统一认证登录」 | 演示站的 `REPAIR_SSO_MOCK_IDP_ENABLED` 没开，或该校没配 SSO（`docs/05` §4.6） |
| AI 问数 40004 | 模型 Key 余额不足 / 未配置（`AI_MODEL_API_KEY`） |
| AI 问数 10004 | 限流（默认 10 次/分钟）——演示前等一分钟，或临时调 `REPAIR_AI_RATE_LIMIT_MAX_REQUESTS` |
| 师傅扫码到场被拒 | 扫的是别的位置码（服务端校验位置一致）；手输这张单的房间码即可 |
| 刚提交的工单不见了 | 应用重启触发了演示重置（演示模式的正常行为） |
| 演示站打不开 | 容器没起来：`docker compose ps`，确认 `repair-app` / `repair-nginx` / `repair-mysql` 都是 Up |
