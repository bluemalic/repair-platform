## 1. URL 约定

```
/{端}/{模块}/{资源}[/{id}][/{动作}]
```

| 端前缀 | 对应前端 | 鉴权角色 |
|---|---|---|
| `/api/student/**` | 学生端 H5（预留小程序） | 学生 |
| `/api/worker/**` | 维修工端 H5（**同一个 uni-app 工程**，按角色路由） | 维修工 |
| `/api/admin/**` | 后勤管理端 | 后勤管理 / 管理员 |
| `/api/ai/**` | 各端共用 | 视上下文 |

示例：

```
POST   /api/student/tickets              提交报修
GET    /api/student/tickets              我的工单（分页）
GET    /api/student/tickets/{id}         工单详情
PUT    /api/student/tickets/{id}/cancel  撤销工单

GET    /api/worker/tickets?status=20     待接工单
POST   /api/worker/tickets/{id}/accept   接单
POST   /api/worker/tickets/{id}/finish   完工并上传结果

POST   /api/admin/tickets/{id}/dispatch   派单
GET    /api/admin/statistics/overview     统计概览
POST   /api/ai/query                      自然语言问数
GET    /api/ai/query/stream               流式问数（SSE）

GET    /api/notification/list             我的通知（分页）
GET    /api/notification/unread-count     未读数（前端轮询用）
PUT    /api/notification/{id}/read        标记已读

GET    /api/tickets/by-code/{code}        按报修码查询
                                          ← 学生扫码报修、维修工扫码到场**共用这一个接口**
```

> **报修码是跨端的关键抽象**：小程序调 `wx.scanCode` 拿到码，H5 让用户手动输入 4 位码，**两者请求的是同一个后端接口**——这样换端不用改后端。

**约定**：

- 资源用**复数名词**，动作用**子路径**（`/accept`），不要用 `/acceptTicket`
- 查询用 `GET` + query 参数；创建用 `POST`；全量更新用 `PUT`；部分更新用 `PATCH`；删除用 `DELETE`
- **动作类接口（派单、接单、核销）用 POST**，因为它们不是幂等的资源替换

## 2. 统一返回体

```java
@Data
public class Result<T> {
    private Integer code;      // 业务状态码，0 = 成功
    private String  message;   // 提示信息
    private T       data;      // 业务数据
    private String  traceId;   // 链路追踪ID，排查问题用
}
```

```json
{
  "code": 0,
  "message": "success",
  "data": { "id": 1857392012345678, "status": 20 },
  "traceId": "a1b2c3d4e5f6"
}
```

**为什么带 traceId**：用户报错时截图给你，你凭 traceId 直接在日志里定位整条链路。面试时这句话很加分。

### 分页返回体

```json
{
  "code": 0,
  "message": "success",
  "data": {
    "total": 137,
    "pageNum": 1,
    "pageSize": 10,
    "pages": 14,
    "list": [ ]
  },
  "traceId": "a1b2c3d4e5f6"
}
```

## 3. 错误码表

**按模块分段，集中管理，禁止散落魔法值。**

| 区间 | 模块 |
|---|---|
| `0` | 成功 |
| `1xxxx` | 通用（参数、鉴权、系统） |
| `2xxxx` | 工单 |
| `3xxxx` | 权限与用户 |
| `4xxxx` | AI 与 SQL 安全 |
| `5xxxx` | 文件与存储 |

| 码 | 含义 | 触发场景 |
|---|---|---|
| `10001` | 参数校验失败 | `@Valid` 校验不通过 |
| `10002` | 未登录或登录已过期 | Token 缺失/失效 |
| `10003` | 无权限访问该资源 | 越权 |
| `10004` | 请求过于频繁 | 限流 |
| `10005` | 系统繁忙，请稍后重试 | 兜底异常 |
| `20001` | 工单不存在 | —— |
| `20002` | 工单状态不允许该操作 | **非法状态跃迁**——这个码很关键 |
| `20003` | 该工单已被其他人接单 | 并发抢单 |
| `20004` | 无权操作他人工单 | **数据权限拦截** |
| `20005` | 工单已评价，不可重复评价 | 幂等 |
| `20006` | 报修码无效或已失效 | 扫码 / 手动输入错误 |
| `30001` | 用户名或密码错误 | —— |
| `30002` | 账号已被禁用 | —— |
| `40001` | 自然语言无法解析为查询意图 | —— |
| `40002` | 生成的 SQL 未通过安全校验 | **安全网关拦截** |
| `40003` | 查询超时，请缩小查询范围 | 熔断 |
| `40004` | 模型服务暂时不可用 | 模型降级 |
| `50001` | 文件类型不支持 | —— |
| `50002` | 文件大小超限 | —— |

> 💡 面试官如果问"你怎么处理并发抢单"，答"`20003` 这个错误码 + 唯一索引兜底"——具体、可信。

## 4. 鉴权约定

- 登录成功后返回 Token，前端放 `Authorization: Bearer <token>` 请求头
- **登录方式：账号密码**（学号 / 工号），**不接微信授权登录**——`wx.login` 只有小程序有，H5 没有，用了就没法跨端
- 服务端用 Sa-Token 校验，权限注解：`@SaCheckPermission("ticket:dispatch")`
- **端前缀与角色绑定**：`/api/student/**` 只允许学生角色访问，拦截器统一校验

## 5. 完整示例（一个接口写全，其余照抄结构）

### 派单

```
POST /api/admin/tickets/{id}/dispatch
```

**请求头**

```
Authorization: Bearer <token>
Content-Type: application/json
```

**请求体**

```json
{
  "workerId": 1857392099999999,
  "remark": "电工班张师傅，优先处理"
}
```

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| workerId | Long | 是 | 维修工ID |
| remark | String | 否 | 派单备注，最长 255 字 |

**成功响应**

```json
{
  "code": 0,
  "message": "success",
  "data": { "ticketId": 1857392012345678, "status": 20, "dispatchTime": "2026-09-10 14:23:01" },
  "traceId": "a1b2c3d4e5f6"
}
```

**失败响应**

```json
{ "code": 20002, "message": "工单当前状态不允许派单", "data": null, "traceId": "a1b2c3d4e5f6" }
```

**幂等说明**：重复派单请求返回同一结果，不会重复写流转日志（依赖「状态前置校验 + 唯一约束」）。

## 6. 接口文档落地

用 **Knife4j** 自动生成，注解写全：

```java
@Operation(summary = "派单")
@PostMapping("/{id}/dispatch")
public Result<DispatchVO> dispatch(
        @Parameter(description = "工单ID") @PathVariable Long id,
        @Valid @RequestBody @Parameter(description = "派单参数") DispatchDTO dto) {
    return Result.ok(ticketService.dispatch(id, dto));
}
```

访问 `http://IP:8080/doc.html` 就能看到在线接口文档 —— **把链接直接写进简历和 README**。
